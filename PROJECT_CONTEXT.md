## 1. Что за проект

- **Живой торговый бот на Bybit spot, реальные деньги.** Главный файл — `spot_bot_vNNN_fixed.py` (сейчас v338).

## 2. Постоянные правила работы (соблюдать всегда)

1. **Только реальные, доказанные фиксы** — каждый баг подтверждаем конкретными строками лога / записями JSON, а не догадками.
2. **Новый версионный файл каждый раунд** для `spot_bot` (`vNNN` → `vNNN+1`). Уже закоммиченные версии **не редактируем на месте** — делаем `cp старый новый`, правим только новый; если старый показал `M` в `git status`, откатываем `git checkout -- старый`.
3. **`ai_brain_advisor_v4.py` правим на месте** (он не версионируется в имени файла, версия — в комментариях-тегах `FIX-vNNN`).
4. **Не перегружать код зря** — не плодить версии и обвязку ради косметики. Явное пожелание владельца.
5. **Отчёт на русском** каждый раунд (`TRADING_BOT_AUDIT_ROUNDNN.md`).
6. **Проверка перед коммитом:** `python3 -m py_compile` + `python3 -m pyflakes | grep "undefined name"` + разбор синтаксиса + поиск задублированных методов.
7. **Отдавать рабочие файлы** через отправку файлов в конце раунда.
8. Владелец пишет по-русски, часто с опечатками — отвечаем по-русски, спокойно и по делу, честно про размер убытков.

## 4. Журнал версий и что каждая исправила

- **v331** (по логу за месяц, 76 МБ):
  - FIX-v331-1: устаревший `current_price` после AUTO-SWITCH (трейлинг/BE считались по цене старой монеты; pnl показывал +17753%). Обновляем цену перед process_fills/manage + защита по соотношению.
  - FIX-v331-2: сверка PnL по факту (IOC-продажа по bid×(1−slip), а отчёт брал цену на момент решения).
  - FIX-v331-3: сторож дрейфа часов `_check_clock_drift()` (25 443 ошибок ErrCode 10002/мес из-за ~20с дрейфа), бампит recv_window, шлёт совет по NTP.
  - FIX-v331-4: ИИ-парсер — собираем все text-блоки, а не `content[0]['text']`.
  - FIX-v331-5: сброс score для непокупаемого символа (цена > MAX).
  - FIX-v331-25: `_clamp_filters_to_strict_floor()` больше не откатывает лестницу ослабления каждый скан.
- **v332:** закрыт провал покрытия breakeven-lock (мёртвая зона между пиком 0.35% и порогом трейлинга 1.4%, где не было реального ордера на бирже). После полной заливки сетки порог трейлинг-ордера опускается до `BE_LOCK_TRIGGER_PCT`. + показ PnL в процентах.
- **v333:** `bad_hours` (плохие часы мозга) раньше влияли только на тайминг SNIPER. Подключили `hour_stats` к гейтингу score во всех режимах (SMART/SAFE).
- **v334:** `_symbol_loss_streak` был в памяти и обнулялся при рестарте — корень зацикливания на убыточной монете. Теперь сериями убытков засеиваем из истории `bot_knowledge.json` при старте. (2 подряд → запрет 4ч, 3 подряд → бан навсегда.)
- **v335:** ступенчатая фиксация прибыли — при пике ≥0.90% гарантируем НЕТТО ≥+0.40%. + кэш сканера 30мин→5мин с проверкой дрейфа цены.
- **v336:** резерв `AI_LOSS_ANALYSIS_RESERVED_CALLS=15`, чтобы сканер не съедал бюджет анализа убытков; `_call_api(purpose=...)`; `_apply_loss_analysis` шлёт TG при любом сбое (раньше молчал); лог `ai_explain_win` через `logging.getLogger('spotbot')` вместо невидимого `print()`.
- **v337:** FIX-v337-HOLD — перед спуском лестницы: если ТЕКУЩИЙ уровень имеет 8+ сделок и WR≥50%, держим фильтры.
- **v338:** FIX-v338-HOLD2 — перед спуском: если ЦЕЛЕВОЙ уровень имеет 8+ сделок и WR<40%, не спускаемся на него. Завершение правила «не понижать фильтры, если понижение даёт минуса».
- **ai_brain_advisor FIX-v339-THINKING**: корень ошибки «ответ без текстовых блоков: types=['thinking']». У `claude-sonnet-5` расширенное мышление включено по умолчанию; при `max_tokens=600` оно съедало весь бюджет, и в ответе не оставалось text-блока. Добавлен `"thinking": {"type": "disabled"}` в тело запроса — весь бюджет теперь идёт на реальный JSON-ответ, вызов дешевле и быстрее.
- **Раунд №47** (без изменений кода): введён постоянный шаблон проверки `AUDIT_CHECKLIST.md` (5 проходов: механика всех 8 файлов → AST → логика правок → прогон ИИ-модуля → прогон торговой цепочки) + два повторно запускаемых симулятора в `audit_tools/` (`sim_run1_advisor.py` — 9 сценариев API на реальном AIBrainAdvisor; `sim_run2_spotbot.py` — 12 проверок на реальном BotKnowledge: relax_level_stats/HOLD/HOLD2/серии убытков/be_lock/hour_stats/персистентность). Все проверки зелёные, v338 + FIX-v339-THINKING подтверждены симуляцией. **С этого раунда каждая проверка идёт строго по шаблону AUDIT_CHECKLIST.md.**

## 5. Аварийные защиты от «залипания» (не дают боту встать намертво)

- streak ≥ 50 → экстренный сброс (ADX→22, turnover→50k);
- 24ч без сделок → агрессивный сброс;
- 48ч без сделок → полный сброс.
- Механизмы HOLD/HOLD2 (v337/v338) только придерживают спуск на слабые уровни, но всегда уступают этим аварийным клапанам. Бот не может простоять >24ч без торговли.
