# Аудит №36 (v330) — гонка между двумя процессами на общем файле

Проверял на этот раз с угла, которого раньше не касался: не "что каждый файл пишет/читает", а "что происходит, когда ДВА процесса лезут в один и тот же файл почти одновременно".

## Находка — реальная гонка между spot_bot.py и smc_bot.py

`smc_signals.json` пишут **два независимых процесса**: `smc_bot.py` — после каждого скана (весь цикл занимает до 100+ секунд — 50 монет анализируются одна за другой), и `spot_bot.py` — в момент входа в сделку (помечает, что сигнал использован, либо добавляет запись "вошли самостоятельно").

Раньше оба делали это без какой-либо координации: прочитать файл → изменить в памяти → записать обратно. Если между чтением и записью ОДНОГО процесса второй процесс успевал сделать свою запись — она **молча терялась**, потому что первый процесс перезаписывал файл своей версией, в которой этого изменения ещё не было. Атомарная запись (временный файл + подмена), которую сделали в прошлом раунде, защищает только от **частичного/повреждённого** чтения — а не от этой гонки, где обе записи технически "целые", просто одна из них стирает другую.

**Что исправил:**
- `spot_bot.py` теперь держит файл открытым с эксклюзивной блокировкой (`flock`) на весь цикл чтение→запись — если `smc_bot.py` в этот момент тоже пишет, он подождёт своей очереди вместо потери данных. На системах без такой возможности (не Linux) бот просто продолжит работать по-старому, ничего не сломается.
- `smc_bot.py` перед своей записью (в конце скана, когда данные в памяти уже могли устареть за 100+ секунд) подтягивает с диска то, что `spot_bot.py` мог успеть дописать за это время, вместо того чтобы стереть это устаревшей копией.
- Заодно нашёл: список "самостоятельных входов" в этом же файле рос бессрочно (каждая сделка без SMC-сигнала добавляла запись, ничего никогда не удалялось) — теперь держится последние 200 записей.

Это не про прибыль напрямую, а про надёжность данных, на которых бот и вы принимаете решения — без этого фикса статистика "сколько сделок было по SMC-сигналу, а сколько самостоятельно" могла быть неточной из-за случайных потерь записей.
