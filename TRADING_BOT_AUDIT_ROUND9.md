## Баг: `ai_score_symbol()` и `ai_analyze_entry()` блокировали торговый поток изнутри самого скана

В прошлом раунде (ROUND8) я нашёл и вынес в фоновые потоки блокирующие вызовы ИИ в командах `/market` и `/forecast`. Но пропустил **два других места**, где `ai_brain_advisor` вызывается не по команде, а **автоматически, изнутри `scan_market_top()`** — то есть прямо в торговом цикле:

- **`ai_score_symbol()`** — вызывается для каждой монеты в скане со `score >= 6.0` (строка ~13260 в `spot_bot_v305_fixed.py`), если `AI_BRAIN_ENABLE=True`.
- **`ai_analyze_entry()`** — вызывается перед входом в выбранную монету (строка ~13934), если `AI_ENTRY_FILTER_ENABLE=True`.

**Второе — не гипотетический риск, а подтверждённый факт**: на вашем скриншоте `/ai_status` в прошлом сообщении было написано **«Фильтр входов: ✅»** — то есть `AI_ENTRY_FILTER_ENABLE` у вас включён, и этот путь реально работает при каждом скане.

Обе функции внутри делают `requests.post()` к Claude API с `timeout=25` секунд — **синхронно, в главном торговом цикле** (`run() → scan_market_top()`). Если Claude API отвечает медленно (или не отвечает, как это, скорее всего, и происходило из-за устаревшей модели, см. ROUND8) — весь скан монет замораживается на до 25 секунд **на каждую подходящую монету**, и вместе с ним замораживается вся остальная торговая логика этой итерации: проверка позиции, стоп-лосс, обработка fills. Это ровно тот же класс проблемы, что уже находил и чинил для `TG.send()` (ROUND6) и `/market`/`/forecast` (ROUND8) — только эти два места я тогда пропустил, потому что они не команды, а автоматические вызовы внутри скана.

### Исправление

В `_call_api()` добавлен параметр `timeout` (по умолчанию 25с — не меняет поведение фоновых вызовов: `ai_explain_loss`, ночной отчёт, `/forecast`, `review_blacklist` — они и так уже выполняются в отдельных потоках, им блокировка не грозит). Для двух синхронных вызовов внутри `scan_market_top()` выставлен короткий `timeout=4.0` — если ИИ не ответил за 4 секунды, скан просто продолжает работу без ИИ-корректировки (как и раньше при полном отказе API), но торговый цикл больше не может зависнуть на 25 секунд посреди скана.

### Проверка всех остальных мест вызова ИИ-советника (полная классификация)

Прошёлся по каждому месту, где `spot_bot` обращается к `self.ai_advisor`:

| Вызов | Где | Блокирует торговлю? |
|---|---|---|
| `ai_explain_loss` | после убытка | Нет — сам создаёт фоновый поток |
| `ai_explain_win` | после прибыли | Нет — не делает сетевых запросов вообще |
| `ai_correlation_signal` | скан | Нет — заглушка, мгновенный возврат |
| `ai_score_symbol` | скан | **Было да → исправлено (timeout 4с)** |
| `ai_analyze_entry` | скан, перед входом | **Было да → исправлено (timeout 4с)** |
| `/market`, `/forecast` | команды TG | Нет — уже вынесены в фон (ROUND8) |
| `is_news_blocked`/`ai_news_filter` | скан | Нет — читает локальный файл с кэшем 60с, не сеть |
| `ai_market_regime`, `check_mode_restore` | скан | Нет — заглушки |
| `check_nightly_report`, `review_blacklist` | раз в сутки/неделю | Нет — сами создают фоновые потоки |
| `ai_optimize_tp` | раз в сутки | Не вызывается — метод не существует, вызов уже защищён `hasattr()`-проверкой (осознанно, см. `[FIX-v296-1]` в коде) |

Больше блокирующих путей не нашёл — этот проход закрывает класс «ИИ-советник тормозит торговлю» полностью, насколько можно судить по коду.
